# Kata Judge Count — Setup Wizard & Live Edit Feature Prompt

## Context & Constraints

The setup wizard lives at `src/app/setup/[id]/page.tsx`. It has multiple phases
controlled by `setPhase()` and saves state via `saveDraft()` (called by `handleNext()`,
`handleBack()`, and `setPhase()`). The competition has two modes:

- **Custom** — operator manually builds categories with `toggleCategorySelection()`
- **WKF mode** — categories auto-generated via `generateWkfCategories()` triggered by
  `handleWkfModeChange()`

Categories are saved in Firestore under the competition document.

### Files you must NOT break
- `setup/[id]/page.tsx` — all existing phases, `saveDraft()`, `handleWkfModeChange()`,
  `handleNext()`, `handleBack()`, `handleDeploy()`, `handleFileUpload()`,
  `handleDownloadTiesheets()`, `toggleCategorySelection()`
- `lib/wkf-categories.ts` — `generateWkfCategories()` must be untouched
- `lib/tiesheet-generator.ts` — bracket generation is unaffected
- Any kumite category settings

## Feature A — Custom Mode: Per-Category Judge Count

### Where to add it
In the category configuration step of the setup wizard, when the operator is
configuring a category that has `type === 'kata'`, show a judge count selector.

### UI spec
Below (or alongside) the existing kata category fields, add:

```
Number of Judges
  ○ 3   ○ 5   ○ 7
```

- Radio buttons, options: 3, 5, 7.
- Default: 3.
- Only visible when `category.type === 'kata'`. Kumite categories do not show this.

### Data model
Add to the category object:

```ts
judgeCount?: 3 | 5 | 7;   // only present on kata categories
```

Persist via `saveDraft()` — no new save mechanism needed, it flows through the
existing Firestore write in `saveDraft()`.

## Feature B — WKF Mode: Global Judge Count for All Kata Categories

### Where to add it
In the WKF mode configuration section (near `handleWkfModeChange()`), after the
operator enables WKF mode, show a single judge count selector that applies to
**all kata categories** generated by `generateWkfCategories()`.

### UI spec
```
Kata Judge Count (applies to all kata categories)
  ○ 3   ○ 5   ○ 7
```

- Radio buttons, options: 3, 5, 7.
- Default: 3.
- Only visible when WKF mode is active.
- Selection stored on the competition document as `wkfKataJudgeCount: 3 | 5 | 7`.

### Propagation
When `generateWkfCategories()` runs, after generating kata categories, set
`judgeCount = competition.wkfKataJudgeCount` on each kata category before saving.
Do **not** modify `generateWkfCategories()` itself — apply the judge count in the
caller (`handleWkfModeChange()` or the step that saves generated categories).

## Feature C — Live Edit: Change Judge Count Before a Kata Event Begins

### Where to add it
In the operator/categories page (`src/app/competitions/[id]/categories/page.tsx`)
or wherever the operator can see the list of upcoming events on a mat.

### Rule
- If a kata category/event is **UPCOMING** (not yet started, no match is IN_PROGRESS),
  the operator may change `judgeCount` for that category.
- If the event is IN_PROGRESS or COMPLETED, the judge count field is read-only/hidden.

### UI spec
In the category row/card for upcoming kata events, show an inline edit field:

```
Judges: [3 ▼]   (dropdown or radio: 3 / 5 / 7)
```

Clicking/changing it:
1. Immediately PATCHes the category document in Firestore.
2. Shows a success toast.
3. The `judgeCount` change is picked up by the scoreboard and operator panel when
   the event is loaded (they read `category.judgeCount` on `loadMatch()`).

### Guard
Before saving, verify the event status is still UPCOMING (re-check server-side in the
PATCH route to prevent race conditions).
